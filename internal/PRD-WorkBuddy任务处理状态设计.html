PRD：WorkBuddy 任务处理流程与状态设计

版本：v1.0日期：2026-09-24状态：评审稿依据：7 张实际界面截图归纳

1. 背景与目标

用户向 WorkBuddy 下发一个任务后（例如"帮我制作一个个人工作台"），界面会经历一系列可见的状态变化：从深度思考、任务拆解、文件读写、命令执行，到最终交付产物。本文档定义这套任务处理逻辑与状态机，明确每种状态的界面展示、用户可用操作与流转规则，作为设计与验收依据。

2. 整体处理逻辑（端到端）

一次任务的处理遵循"理解 → 规划 → 执行循环 → 交付"四段式：

  1. 接收与理解：解析用户消息（文本 / 附件 / @文件），判断任务类型与复杂度；
  2. 深度思考与规划：复杂任务先输出思路摘要，再生成任务计划（Task List），拆成可追踪的条目；
  3. 工具执行循环：按计划逐条执行，期间反复调用工具——读文件、写/编辑文件、运行命令、联网检索等，每一步都实时流式展示；
  4. 交付：汇总结果生成最终回复，附上产物卡片（文件）、变更记录，任务状态更新为已完成。

3. 状态总览（共 6 种）

编号状态界面显示用户可用操作流转去向
S0 就绪 / 已发送 消息气泡已上屏，助手卡片占位等待响应 撤回消息、继续补充输入 → S1
S1 思考中 / 生成回复中 「深度思考」标签；正文流式逐字输出；底部显示「生成回复…」及停止按钮 停止生成；折叠/展开思考过程 → S2 / S3 / S5；停止 → S6
S2 任务计划（Plan） 「任务列表 ▾」折叠区：待执行条目为空心圆，执行中为旋转图标，完成为对勾；计划类工具调用单独成卡片 展开/折叠；Plan 模式下确认或修改计划 → S3；全部完成 → S5
S3 工具执行中 按工具类型展示明细卡（见 §4）；进行中项灰色/加载态 停止任务；点开文件/路径跳转查看 循环回 S3 或 → S5；失败 → S6
S4 等待用户确认 计划审批、敏感操作授权、选择题（AskUserQuestion）等中断卡片 批准 / 拒绝 / 选项作答 / 自由输入 → S3 继续；拒绝 → S6
S5 已完成 最终回复（标题、要点、加粗结论）+ 产物卡片 + 「查看所有产物 / 查看所有变更」入口 + 操作栏 + 时间戳 下载/预览产物、查看 diff、复制、点赞点踩、引用追问、重试 追问 → 新一轮 S1
S6 失败 / 已停止 / 需处理 红色感叹号标记（任务列表中的失败条目、命令报错输出、语法校验失败提示） 重试、根据错误提示补充信息后重新下发 重试 → S1
左侧任务面板中每条历史任务同样沿用这套状态：绿色对勾 = 成功，红色感叹号 = 失败/异常，时钟图标 = 进行中。

4. 执行态（S3）工具卡片的子状态明细

执行期间所有动作都以"图标 + 摘要行 + 可展开详情"的卡片形式流式展示，共 4 类：

子状态图标前缀摘要行内容展开详情示例（对应截图）
读取文件 👁 读取 操作名 + 文件绝对路径 + 行范围 路径可点击定位到具体行 「读取 …personal-workbench/index.html L300-末尾」（图4）
编辑文件 ✏️ 编辑 操作名 + 文件路径 + +N -M 增删行统计 代码 diff，新增行绿底、删除行红底，可点开整文件 「编辑 index.html +44 -0」并展示绿色 diff 块（图5）
写入文件 📝 正在写入文件 当前写入的目标文件名 写入完成后转为产物卡片 「构建个人工作台应用 → 正在写入文件」（图3）
运行命令 ⌨️ 运行命令 shell 类型 + 命令摘要 完整命令 + 标准输出/报错，成功打 ✓，失败展示报错文本 bash 运行 node 语法校验，输出 OK 后打 ✓（图6）

此外还有记忆写入卡（如「写入 …/memory/2026-09-24.md」），属于低感知后台动作，同样流式展示但不打断主线。

5. 完成态（S5）交付规范

  • 正文：结构化总结——先给结论，再分模块列要点，关键功能加粗；避免大段流水账。
  • 产物卡片：生成的文件以卡片呈现（如图7 的 index.html），支持预览与下载。
  • 回放入口：「查看所有产物 (N)」「查看所有变更 (N)」，可回看本次任务产生的全部文件与每一处 diff。
  • 操作栏：复制、点赞/点踩、引用、更多、重试/切换模型等，均固定在回复末尾，附时间戳。
  • 后续建议：可附"下一步可以做什么"的引导项，降低用户二次发起成本。

6. 异常与边界

场景表现处理
用户点击「停止生成」流式中断，保留已生成部分，标记已停止可继续追问或重试
命令/校验失败运行命令卡展示报错输出；智能体会自行读取报错、修改后重跑多次失败才上抛为 S6
任务整体失败任务面板条目标红（如图1 侧栏「生成 AI 表格报价页面 ⚠」）支持重试；失败原因写入回复
需授权的高危操作中断并弹出确认卡（S4）用户批准后才继续执行
历史任务回看侧栏任务列表按时间排列，状态图标即最终状态点开可还原完整过程记录

7. 验收标准（节选）

  • 任意时刻用户都能明确看出"当前处于哪种状态"：标签、图标、加载动效三者至少其一存在；
  • 生成中（S1）必须提供停止按钮，且停止后内容不丢失；
  • 每次文件编辑必须展示 +N -M 统计与 diff；每次命令执行必须展示命令与输出及成败标记；
  • 完成态必须提供产物入口与变更入口，缺一视为不达标；
  • 失败必须有可视标记与重试路径，不允许静默失败。
